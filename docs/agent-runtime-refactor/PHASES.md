## P4 统一动作、读回与操作记录

### 开发步骤

1. 建立 act 对象校验和后端路由，正常路径以 ref 为目标。DOM 使用定位器，UIA 按已支持 pattern 与应用行为执行，物理交互使用当前几何。
2. 模型提供动作意图和已观察对象，旧 goal/decide/KB 自动挑选退出该路径。
3. 支持输入 replace/insert、checkbox 设值、选择项、右键/双击、hover、滚动、拖拽、文件 attach 和目标关闭，覆盖旧工具的实际交互能力。
4. 默认物理移动使用快速确定的路径，专门 drag/hover/特定应用时序由对应实现处理。统一动作后的等待窗口。
5. 在执行前校验目标 identity、可用状态、几何与输入焦点。身份无法确认时返回新的局部观察。
6. 引入 operation_id 和逐步执行记录，利用 exec.callId 为重复请求建立跨 epoch 稳定关联。stateDir 下的轻量持久 journal 在派发前写入必要阶段，派发后更新结果和证据。完整结果和幂等摘要使用不同保存期。
7. 处理中途崩溃恢复。存在可能已派发的步骤时恢复为 unknown，提供查询与现场读回，保留已完成步骤。
8. 实现短批量顺序执行。每步执行前重验引用，导航、弹窗、目标变化和预期失败时返回停止位置。
9. 根据动作类型读取值、状态、页面身份或局部变化。结果使用协议中的 dispatch、outcome、expectation 词汇，并给出可继续使用的观察。
10. 将 stop、AbortSignal、超时、输入租约与队列取消收归同一 operation 生命周期。status follow 取消只影响本次查询，原始执行请求的取消撤销后续输入。读请求重连恢复和动作重复请求共用明确策略。
11. 长操作在有限初始等待后返回 handle，status 支持有限 follow，操作记录保留超过展示缓存淘汰周期的对账依据。
